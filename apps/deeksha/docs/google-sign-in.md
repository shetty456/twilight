# Google sign-in integration

Deeksha uses `packages/auth` to obtain a Google ID token and exchanges it for
Origin JWTs. The shared provider can be reused by other Twilight apps; each app
supplies its own Google OAuth client IDs and Origin token store.

## Origin token exchange

The native app calls `POST /api/v1/auth/google/token/` with
`{ "id_token": "<Google ID token>" }`.

The server must verify Google's signature, issuer, expiry, and audience against
the configured web/server client ID, use the verified `sub` to find or create a
Google identity, then return `{ "access": "<JWT>", "refresh": "<JWT>" }`.
Invalid tokens should return 400 or 401. Do not trust the email or subject sent
separately by the client.

## Google Cloud setup

- Register an Android OAuth client for `com.twilight.deeksha` with the signing
  certificate SHA-1 for each build configuration.
- Register an iOS OAuth client for the app's bundle ID.
- Register a web OAuth client for Origin. The app defaults to Deeksha's configured
  web client ID; override it for another backend using
  `--dart-define=GOOGLE_SERVER_CLIENT_ID=<web-client-id>`.
- Supply the iOS client ID using
  `--dart-define=GOOGLE_IOS_CLIENT_ID=<ios-client-id>`.
- Add the iOS client's reversed ID as a `CFBundleURLTypes` URL scheme in
  `ios/Runner/Info.plist`. This value is generated by Google Cloud for the
  registered iOS client.

Google sign-in is the default logged-out screen. The existing phone flow can be
shown for future testing with `--dart-define=DEEKSHA_GOOGLE_AUTH_ENABLED=false`.
A missing server client ID disables the Google button.
The current web build also stays disabled because Google's web SDK requires its
own rendered sign-in button.

The app exchanges the Google ID token directly with Origin. After a successful
exchange it stores the Origin JWT pair and the Google account's email, name, and
photo URL. The profile screen shows those details when available.
